# TCO-Vergleich Build vs. Buy

## Kernidee

Der TCO-Vergleich zwischen Build und Buy muss über 3-5 Jahre laufen und alle Kostenposten einschließen — sonst wird Buy immer billiger aussehen als es ist, oder Build immer teurer.

## Im Detail

**Build TCO (typische Kostenposten):**

| Kategorie | Posten |
|---|---|
| Entwicklung | Team-Monate × Stundensatz × Dauer (3-12 Monate) |
| Infrastruktur Initial | GPU-Kosten, Cloud-Setup, Datenaufbereitung |
| Wartung jährlich | oft 30-50% der Entwicklungskosten pro Jahr |
| Updates & Replacement | Modell-Updates, Re-Training, Architektur-Änderungen |
| Internes Support-Team | dedizierte Ressourcen für Betrieb und Support |

**Buy TCO (typische Kostenposten):**

| Kategorie | Posten |
|---|---|
| Lizenz | jährlich, pro Nutzer oder pro Nutzung |
| Implementation Services | Einführungsberatung, oft 0,5-2× Jahreslizenz |
| Customization | Anpassungen an eigene Anforderungen |
| Integration | Anbindung an bestehende Systeme |
| Schulung | initiale Schulung + jährliche Auffrischung |
| Vendor Management | internen Aufwand für Vendor-Beziehung |

**Faustregel:** Build-Entwicklung kostet oft 3-5× mehr als erwartet. Buy-Implementierung und Customization kosten oft 1,5-2× mehr als die Lizenz.

**Typisches Ergebnis:** Buy ist kurzfristig (Jahr 1-2) günstiger, Build kann ab Jahr 3-5 aufholen — wenn der Build funktioniert.
