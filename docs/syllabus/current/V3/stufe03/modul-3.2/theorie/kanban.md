# Kanban-Grundlagen

## Kernidee

Kanban ist einfacher als Scrum: Du visualisierst deine Arbeit auf einem Board (To Do → In Progress → Done), begrenzt die gleichzeitige Arbeit (WIP-Limits), und optimierst den kontinuierlichen Fluss. Keine Sprints, keine Rollen, weniger Zeremonien. Ideal für laufende Arbeit statt Projektentwicklung.

## Im Detail

**Kernprinzipien von Kanban:**

1. **Visualisiere die Arbeit:** Jedes Arbeitspaket ist eine Karte auf einem Board. Spalten zeigen den Status (z.B. Backlog → To Do → In Progress → Review → Done).

2. **Begrenze Work in Progress (WIP):** Jede Spalte hat ein Maximum. Wenn "In Progress" auf 3 begrenzt ist, darf kein neues Item gestartet werden, bevor eines fertig ist. Das verhindert Multitasking und erzwingt Fokus.

3. **Manage den Fluss:** Beobachte, wo Karten stecken bleiben (Bottlenecks). Optimiere den Durchsatz, nicht die Auslastung einzelner Personen.

4. **Kontinuierliche Verbesserung:** Regelmäßig reflektieren und anpassen, aber ohne die strikten Zeremonien von Scrum.

**Wann Scrum, wann Kanban?**

| Kriterium | Scrum | Kanban |
|---|---|---|
| Arbeitstyp | Produktentwicklung mit Iterationen | Kontinuierlicher Service-Betrieb |
| Rhythmus | Feste Sprints (2 Wochen) | Kontinuierlicher Fluss |
| Rollen | PO, SM, Dev Team | Keine vorgeschriebenen Rollen |
| Zeremonien | 5 Events fest definiert | Flexibel, weniger formell |
| Planung | Sprint-weise | Item-weise |

**Kanban für persönliches Lern-Management:** Besonders gut geeignet, um deinen eigenen Lernfortschritt zu visualisieren. Board mit Modulen als Karten, WIP-Limit 2-3 (nicht mehr als 3 Module gleichzeitig).
