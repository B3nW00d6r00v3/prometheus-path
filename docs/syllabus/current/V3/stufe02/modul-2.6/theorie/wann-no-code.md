# Wann No-Code ausreicht, wann nicht

## Kernidee

No-Code ist wie ein Automatik-Getriebe: fuer 80% der Fahrten perfekt, aber im Rennwagen willst du schalten koennen. Fuer schnelle Prototypen, einfache Workflows und Stakeholder-Demos ist No-Code unschlagbar. Fuer Performance-kritische Anwendungen, komplexe KI-Pipelines und Production mit hoher Last brauchst du Code.

## Im Detail

**Staerken von No-Code:**

- Schneller Prototyp (Stunden statt Wochen)
- Einfache Workflows (5-10 Schritte)
- Keine Infrastruktur-Verwaltung
- Stakeholder-Demos und MVPs
- Nicht-technische Teammitglieder koennen selbst bauen

**Grenzen von No-Code:**

- Komplexe Datenstrukturen
- Performance-kritische Anwendungen
- Fortgeschrittene KI-Pipelines (Custom Embeddings, Fine-Tuning)
- Production mit hoher Last
- Vendor-Abhaengigkeit (Lock-in)

**Faustregel:** Fuer 80% der typischen Aufgaben reicht No-Code, fuer die spannenden 20% braucht es Code. Wer No-Code beherrscht, kann spaeter bewusst entscheiden, wann sich der Aufwand fuer Code lohnt -- und das ist genau die Motivation fuer Modul 2.7.
