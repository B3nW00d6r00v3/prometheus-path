# Vibe-Coding-Patterns

## Kernidee

Vibe-Coding funktioniert wie ein Gespraech mit einem Architekten: "Baue mir ein Haus" klappt nicht, aber "Baue mir ein zweistoeckiges Haus, Erdgeschoss offen, Kueche links, Bad oben rechts" klappt hervorragend. Praezise Beschreibungen, ein Feature pro Iteration, klare Stack-Vorgaben -- das sind die Patterns, die funktionieren.

## Im Detail

**Was funktioniert:**

- **Praezise Beschreibungen** -- "Erstelle eine React-App mit einer Suchleiste oben, darunter Karten-Layout mit Titel, Beschreibung und Bild pro Eintrag" statt "mach eine App fuer meine Daten".
- **Iteratives Verfeinern** -- starte einfach, fuege Features Schritt fuer Schritt hinzu. "Fuege jetzt eine Filter-Funktion nach Kategorie hinzu."
- **Ein Feature pro Iteration** -- nicht alles auf einmal. Jede Iteration sollte eine klare, testbare Aenderung sein.
- **Klare Zielsysteme/Stack-Vorgaben** -- "Nutze React + Tailwind CSS" statt "mach es schoen".

**Was nicht funktioniert:**

- **Vage Aufgabenstellungen** -- "mach eine coole App" fuehrt zu durchschnittlichen Ergebnissen.
- **Komplexitaet in einem Schritt** -- "baue mir ein komplettes CRM mit Authentifizierung, Dashboards und Reporting" ueberfordert jedes Tool.
- **Erwartung von Produktions-Reife** -- Vibe-Coding-Outputs brauchen anschliessend Code-Review und Refactoring fuer Production.
